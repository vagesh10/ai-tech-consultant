# Task 1: Knowledge Brain

A knowledge retrieval system for Brilliant Directories support documentation. It crawls support articles, stores article content, creates a semantic vector index, and provides an API for answering questions with source references.

## Features

- **Sitemap-based ingestion:** Discovers support articles from the Brilliant Directories support sitemap.
- **Article storage:** Stores crawled article content and tracks changes between syncs.
- **Semantic retrieval:** Uses Sentence Transformers (`all-MiniLM-L6-v2`) and ChromaDB to retrieve relevant articles.
- **Source references:** Returns article titles and URLs with answers.
- **Abstention:** Avoids answering when relevant documentation is insufficient.
- **Escalation management:** Records unsupported questions and tracks their status and resolution.
- **Feedback collection:** Stores positive or negative feedback, comments, and timestamps.
- **Daily synchronization:** Updates stored articles and rebuilds the vector index after a successful crawl.
- **Image text extraction:** Supports OCR-based extraction of text from article images.
- **Automated tests:** Includes a pytest test suite.

## Setup

Run these commands from the `task1-knowledge-brain` directory.

### 1. Create and activate a virtual environment

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 2. Install dependencies

```powershell
python -m pip install -r requirements.txt
```

### 3. Configure environment variables

Review `.env.example` and create your local `.env` file with the required settings.

Do not commit `.env` or publish API keys, passwords, or other secrets.

The current local development configuration uses mock-answer mode. In this mode, retrieval can be tested without making paid Claude API calls, but the mock response is not generated by Claude.

## Running the API

From the `task1-knowledge-brain` directory, activate the virtual environment and run:

```powershell
uvicorn app.api.server:app --reload
```

The API will be available at:

- API base URL: `http://127.0.0.1:8000`
- Interactive API documentation: `http://127.0.0.1:8000/docs`
- Health check: `http://127.0.0.1:8000/health`

## API Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/health` | Check API health |
| POST | `/ask` | Retrieve relevant documentation and answer a question |
| POST | `/escalations` | Create an escalation |
| GET | `/escalations` | List escalation records |
| PATCH | `/escalations/{id}` | Update escalation status or resolution |
| POST | `/feedback` | Submit answer feedback |
| GET | `/feedback` | Retrieve feedback records |

Use the interactive Swagger documentation at `/docs` to inspect request schemas and try each endpoint.

### Example: Ask a question

The following request illustrates the question format. Follow the actual schema displayed in Swagger if additional fields are required.

```json
{
  "question": "How do I configure social media sharing SEO?"
}
```

A successful response can include an answer, source references, an abstention flag, and an escalation ID.

### Example: Unsupported question

Ask a question outside the available support documentation, such as:

```json
{
  "question": "How can I repair my car's engine?"
}
```

When no sufficiently relevant documentation is found, the system is expected to abstain and create an escalation.

## Ingestion and Daily Synchronization

The crawler discovers support articles from the sitemap, retrieves article content, and updates the local article store.

To run the daily synchronization script:

```powershell
python -m app.scripts.daily_sync
```

The synchronization workflow crawls articles and checks for failures. The vector index is rebuilt only when the crawl is considered successful. A new index is activated after the rebuild completes successfully.

The verified local run indexed **1,696 articles**.

The local database and vector index are generated application data. Back them up if you need to preserve them.

## Image Text Extraction

The project includes OCR support for extracting text from article images. Tesseract OCR must be installed and configured for the OCR workflow to run.

Review the scripts under `app/scripts/` for the available image-processing commands.

## Current Limitations

- **Mock-answer mode:** The current local configuration returns a mock response. It does not provide real Claude-generated answers.
- **External API credentials:** Real Claude-generated responses require valid Anthropic API configuration and available API access.
- **Documentation coverage:** Answers depend on the content available in the indexed support articles.
- **Local development:** The instructions above describe a local setup; production deployment and security configuration must be handled separately.
